# 功能 8 · 销售日报转入月度报表

销售员工可以一次提交一天或多天的截图、复制的日报正文、导出文件。结果是员工当月 Excel 草稿以及可按日期复查的日报明细。使用 WORKFLOW.md 中的同一项目、员工和总结月份。

## 从日报提取事实

1. 看报告标题、作者、填报日期和正文，把同一日报的滚动截图拼起来。相邻截图的重叠段只读一次。页底跳转的下一位员工、批注、头像、奖励和手机状态栏都不属于日报。每位员工每月单独调用程序；同名按已有员工身份核实。身份或残句无法确认时列出疑问。平台无法读图时请员工粘贴文字或提供可读导出。
2. 保留工作地点、日报自报客户数、重点客户进度、今日总结、明日计划、可辨认的指标和来源。重点客户栏可能只有单位名；需结合今日总结找实际动作。地点是行程背景，异地电话联络仍记为沟通。已发生的动作逐件提取，原文保留在明细，月报用“动作＋对象＋已知结果或障碍”写一至两句。
3. 分清业务阶段。例如“与经销商沟通授权事宜”可整理成“跟进项目授权，与经销商沟通办理事宜”；“验收报告签字”可写成“办理验收报告签字”。只有原文明确时才写授权获批、通过验收、成交或回款。“暂时用不上”“需负责人决定”“资质受限”等信息保留为客户反馈或推进障碍。医院的周标本量、其他厂商的报价、代理商的反馈均要保留归属。
4. 明日拜访、计划试用装机等只保存在日报待办，可放在相关工作项 K 栏；到次日有实施记录后才补入实绩。跨到下月也要先由员工选定才写入下月计划页。日报的“客户数量”、正文列了几条、独立客户数、拜访次数是不同统计口径。不要累加每日客户数作为月度独立客户数，或用红黄绿灯快照推算订单额。指标标签与数字无法对应时留在待核问题，保留原文。

## 归并为月报

先用 show 取本月原计划、全部记录和已有 sales_reports。优先匹配原计划，以客户和项目标识串起同一项目多天的进展。在月报写最后已证实的节点、重要结果及仍存的障碍。独立走访保留各自日期。同一活动的重点进度和正文仅引用一条明细。不同医院或渠道即使同名产品，也要在台账中分开。

按工作本身判断点、线、面。例行接洽、单据签收等点事项可按“客户回访”“交付单据办理”归并；有明确交付的需求调研、演示反馈可归线；有跨周阶段证据的准入或渠道项目可归面。月报每类最多五项，可以少于五项。超过容量时，先归并同客户同项目的连续推进，再归并同阶段、同业务目的的事项，例如“渠道对接与决策人跟进”。保留重要客户的关键结果和阻碍；避免以“日常销售工作”吞掉差异。每条分组都关联全部对应明细，一条明细只计算一次。正文不堆叠客户流水，不截掉第六项。

## 提交与核对

向 report.py 传 action=sales_daily，以及 name、department、month、reports、rows。先对同一报告合并重叠页面，reports 每项包含 author、date、sources（文件名、页码或粘贴来源）、today、events。可选 location、customer_count、focus、tomorrow、metrics、questions。其中 today、focus、tomorrow 为栏目原文。一天确有两份独立日报时用稳定的 report_id 区分，重发同一份沿用原编号。只补到缺失栏目时可略去已存栏目；同一栏出现两个版本时指出差异、核实后再办理。

events 沿用 record 的 raw、text、kind、plan、result 等字段；raw 须能在 today 或 focus 的对应原文中定位，section 默认为 today，日期和来源由程序补齐。先按整份日报去重，再用 show 中的编号匹配已记事项。若重复上传，按已有编号或本次别名引用一次。rows 遵循 WORKFLOW.md 的 batch 分组规则，覆盖本月所有已分类明细和计划；new:0、new:1 按 reports 的顺序及各自 events 的顺序连续编号。

示例（虚构）：

```json
{"action":"sales_daily","name":"示例员工","department":"销售部","month":"2026-11","reports":[{"author":"示例员工","date":"2026-11-19","sources":["日报截图第1、2页"],"today":"与甲渠道沟通资料授权，需负责人确认。","tomorrow":"回访乙医院。","events":[{"kind":"点","raw":"与甲渠道沟通资料授权，需负责人确认。","text":"跟进甲渠道资料授权","result":"已沟通，待负责人确认"}]}],"rows":[{"kind":"点","key":"渠道授权沟通","ids":["new:0"],"cells":{"C":"渠道授权跟进","D":"与甲渠道沟通资料授权","F":"已与渠道对接，待负责人确认","J":"11月19日销售日报"}}]}
```

如果程序提示某类超过五项、明细有遗漏或重复，助手自行重新归组、核对编号并再次提交；同一项目在两天有实际活动时保留两天的明细。后续继续上传时沿用已有汇总行 key，结合新进展重写结果，让手工修改仍能按同一项核对。

返回草稿链接、各分类条数、典型归并项、待办和待核问题。询问某一行的依据时，用 compact_rows 对应的 ids 查 records，再按 sales_reports 的 record_ids 找到日期、原文和来源。只有员工要求时才进入定稿或发送流程。
